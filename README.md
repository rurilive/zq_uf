# crashdedupe（surfacemap）

安全方向的小工具，把模糊测试一晚上产出的几千份崩溃样本**按崩溃原因归并**成
少量真实问题，而不是按文件数报问题，也不是只按栈顶函数粗分。

## 归并依据

同一条崩溃记录（crash）带 `id`、`target`、`stack`、`signal`、`fault_addr`、
`insn`（出错指令）、`regs`（寄存器）、`abort_message`。归并前先归一化：

1. **调用栈归一**：去掉帧偏移（`parse_obj+0x12` → `parse_obj`），未符号化的
   纯地址帧折叠成 `<addr>`，截断到前 8 帧后做序列相似度比较；
2. **出错指令归一**：去掉指令地址与立即数具体值（立即数按语义分类），
   保留助记符、寄存器、访问类型（read/write/call/...），识别内存操作数中的
   寻址（故障）寄存器；
3. **寄存器状态**：只保留出错指令涉及的故障寄存器，值按语义分类
   （`zero`/`heap_or_map`/`stack`/...），不比较具体地址；
4. **故障地址**：`0x0` 与低地址字段偏移（如 `0x10`）归为同一类
   `null_deref`，同因的 NULL 解引用不会因偏移不同被拆开；
5. **信号 / abort 消息**：信号不同、断言消息骨架不同一律分开。

匹配采用两级：信号、栈顶、访问类型、故障地址类等硬条件先分桶，桶内再按
栈相似度 0.45 + 指令相似度 0.40 + 寄存器分类 0.15 综合打分，过 0.7 阈值且
各硬门槛通过才并入。**栈相似但出错指令/故障寄存器不同的问题保持独立。**

## 入口

- `triage(crashes, version=None)`：归并一批样本，返回受影响条目、本批新增
  问题数与合并样本数。条目保留**全部样本编号**，并按信息完整度选一份
  **代表样本**用于复现，`match_basis` 记录归并依据和每次匹配的维度明细；
- `report()`：测试同学视角的汇总——真实问题数、按目标的样本/问题分布、
  回归条目数与每条的代表样本。

人工可以再调整：`merge_issues(ids)` 合并、`split_issue(id, groups)` 拆分、
`close_issue(id, fixed_version)` 标记修复。人工操作都进条目历史。

## 生命周期

- 条目在 `v1.2.0` 修复关闭后，若后续版本再次收到**同因**样本，条目自动
  重新打开（状态 `regressed`），记录 `fixed_version` 与回归版本，原样本
  全部保留；
- **已关闭条目不会静默接收任何样本**：同因样本触发重开后才并入，不同因
  样本另开新条目。

默认进程内存储；`use_store(path)` 切到 JSON 文件持久化，跨夜/跨进程保留
条目状态（第二天重跑仍认得昨天关闭的问题）。

## 运行

```
python3 -I demo.py
python3 -I -m unittest discover -s tests -t .
```
