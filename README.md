# crashmin / privpath

提权路径梳理小工具。把「权限」建模为节点、「可执行操作」建模为有向边
（`needs -> effect`），从低权限账号出发枚举完整的多跳提权路径，并把每一步的
前提、所用账号、产生效果、依赖配置和阻断点全部留档。

## 解决的问题

- 换个账号同一条路径是否还成立，需要重新人工摸配置——路径按起点分别记录；
- 报告只写「能提权」不写经过哪几步——每条路径保留有序步骤，可逐步复现；
- 走不通的分支随手丢弃——阻断分支带原因保留；
- 配置变化后不知道哪些路径受影响——步骤标注配置依赖，变更后单独标出；
- 跨账号复现失败就从清单删掉——原结论保留，只追加失败原因；
- 测试账号散落各处——路径账号和复现账号统一进 `accounts` 清单，方便回收。

## 数据模型

操作（ops 列表中的一项）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `op` | 是 | 操作名 |
| `needs` | 是 | 执行所需权限 |
| `effect` | 是 | 成功后获得的权限；空串表示不产生新权限 |
| `preconditions` | 否 | 前提条件名列表，复现时逐项确认 |
| `config` | 否 | 该步骤依赖的配置项，用于配置变更影响分析 |
| `account` | 否 | 执行该步实际使用的账号（如窃得的服务账号），缺省用起点账号 |

`walk(start)` 的入参：`account`（必填）、`role`（默认 `user`）、`ops`、
`conditions`（前提当前状态，`{名称: bool}`；显式为 `False` 才阻断，
未给出的前提只记录不判定，留给复现时确认）。

## 入口

### `walk(start)`

从起点枚举所有简单路径（带环检测，不死循环），返回：

- `reachable`：可达权限，按发现顺序；
- `paths` / `by_target`：完整路径，按目标权限归档，每步含前提、账号、效果、配置；
- `steps`：去重后的可执行操作；
- `preconditions`：全部待确认前提；
- `blocked`：走不通的分支，带 `status=blocked` 和阻断原因
  （前提不满足 / 所需权限不可达）；
- `accounts`：路径中用到的账号；
- `config`：路径依赖的配置项；
- `affected`：被配置变更标记的配置项；
- `reproductions`：该起点的跨账号复现记录（重新 walk 也保留）。

### `config_changed(items)`

通知配置项变化，返回受影响的起点及命中的配置项；标记累积保留，
直到对该账号重新 `walk`。

### `record_reproduction(start, account, target, reason, ok=False)`

登记一次跨账号复现。失败不删除原路径结论，只追加失败原因和复现所用账号。

### `report()`

汇总全部起点：按目标权限归档的路径、阻断分支、前提清单、配置依赖
（每个配置项对应到具体 `起点->目标`）、配置变更影响、复现失败清单、
全部涉及账号（含复现账号，供回收）。

### `reset()`

清空全部记录。

## 演示与测试

```bash
python3 demo.py                       # 多跳、阻断、配置变更、复现失败全流程
```
