# configdrift

安全方向的漏洞工单流转小工具，当前按传入值直接改状态。
现状不校验进入条件，关闭不需要复测，同一漏洞的重复工单也不会合并。

流转规则：open → fixing → pending_retest → closed，逐级流转。
进入 fixing 需责任人，进入 pending_retest 需修复证据，关闭需复测通过。
反向流转即退回，必须填写原因（含类型），复测失败自动退回 fixing。
同项目同漏洞编号的重复工单自动合并到已有工单，保留原编号。
状态变更记录前后值、操作人和原因，统计变更次数与退回原因类型。
report(project) 返回工单列表、卡住工单（无责任人或待复测无结果）、
重复合并记录和退回原因统计。
